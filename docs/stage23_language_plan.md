# Stage 23 语言评估点 — 设计草案 (Language Evaluation Point)

> Status: **design draft** (2026-10-28). 触发条件: 平衡相位决议入档后
> (op 监控带接受), 语言是 8-15 岁的关键门之一。本文件只定义"评什么、
> 判据、边界、顺序" — 不动训练。

---

## 1. 背景与既有资产

| Asset | 位置 | 状态 |
|---|---|---|
| LanguageGeneration (Qwen2.5-7B-Instruct 4bit, **冻结**) | `src/models/language_generation.py` | 存在: describe/explain/dialogue; LLM 不做推理只做翻译 |
| LLMFusionBridge (视-语 FiLM) | `src/models/llm_fusion.py` | 存在 |

**哲学边界 (来自既有设计与北极星)**:
- LLM **只翻译, 不决策** (reasoning 在神经符号层) — 防止外部知识注入。
- 语言接入 = 发育的一步 (命名/描述/指令), 不是外挂。

## 2. 评估点要回答的三个问题

1. **L-out (说)**: 智能体能否用语言忠实描述它所感知/推断的世界?
2. **L-in (听懂)**: 智能体能否把简单指令映射为行为 (grounding)?
3. **L-reason (用语言推)**: **不做** (违反"从零发育"; 记录为明确排除项)。

## 3. 预注册判据 (honest)

| Milestone | 判据 | 口径 |
|---|---|---|
| **M3a L-out 接地** | describe 的忠实度: 描述中的对象/属性/关系与场景事实一致率 **≥0.8**; 幻觉率 (描述了场景中不存在的对象/事件) **≤0.1** | 场景事实由 env state 生成的真值表 (对象数/类别/颜色/位置关系); 混合场景包括遮挡中 (用 last_known, 代表"记忆里的语言") |
| **M3b L-in 指令** | 简单指令 (10-20 条模板: "去拿 X"/"找到消失的 Y") → 目标选择/行为匹配 **≥0.7**; 且不降低 op (回归监控带不变) | 指令由模板生成 + 行为由贪婪执行检查; 与无语言基线对比 (相同 seed) |
| **决策** | M3a 过 → 语言输出常开 (telemetry); M3b 过 → 指令作为可选目标源 (M2 的课程之上); 任一未过 → 记录诚实缺口, 语言维持输出层 | — |

## 4. 实施顺序 (小步)

1. **真值表工具**: 从 env state 生成场景事实 JSON (对象/类别/颜色/遮挡关系);
   对 ckpt 录制 N=20 场景 → 供 describe 评测。
2. **L-out 电池** (现有 LanguageGeneration + run_language_eval.py 扩展):
   贪心解码, 每场景 1 次; 人工规则化匹配 (类别词/颜色词/数量词/存在性)。
3. **L-in 电池**: 指令模板 20 条 × 5 场景; 行为检查 (是否朝目标移动/到圈)。
4. **开关**: 语言输出 telemetry 常开; 指令跟随为 config 门控。
5. **硬件记录**: 3080Ti 12GB: Qwen-7B 4bit 加载 (~5GB) + 训练模型 (2.3GB)
   → 显存紧张但可行; 若 OOM → 语言评测独立进程 (加载模型副本, 不与训练同进程)。

## 5. 风险 / 诚实守卫

- **幻觉**: 语言模型倾向于"编"。判据必须用场景真值表核对, 不看"像不像人话"。
- **评测作弊**: describe 由冻结 LLM 生成, 但**评分是规则化核对**; 不得人工挑例。
- **语言拐杖**: 任何"指令帮助 op/广度提升"的声明必须与无语言基线 (同 seed) 对比。
- **哲学**: LLM 冻结且只做接口; 若将来发现它的"知识"在替智能体做决策, 立即隔离。
- **规模声明**: 语言门=接口层接地; 不等于"掌握语言" (词汇/语法/叙事是更长的线)。

## 6. 与北极星的关系

```
语言 = 四道硬门之一。本评估点的工作定位:
  "从说到听懂" — 让语言成为发育的一部分 (命名世界、接收目标),
  而不是终点。语言能力声明 (词汇量/句法/叙事) 不在本次范围。
```

## 7. M3a 结果与实现决策 (2026-10-29)

**仪器诚实性事故与重建**:
- v1 (2026-10-28 夜): 20 场景全部 num_objects=8 / kinds 相同 (3D 世界
  固定生成) — 真值表无区分度; 评分 count_ok = 文中出现数字 8, 幻觉只查
  种类词 (恒同 → 永远 0)。**0.55 作废, 记为自欺工具 (B16)**。
- v2 仪器: 16 程序化场景 (数量 3-12, 种类子集, 遮挡 0..总数) + 8 真实
  回合; 严格评分: 明确总数=真值, 隐藏数精确匹配, 可见+隐藏自洽,
  矛盾数字/虚假种类 = 幻觉。

**基线 (冻结 Qwen2.5-7B-4bit 裸描述, 24 场景)**: faith 0.125, hall
0.458 — 编数字、自相矛盾。**科学结论: 事实接地必须来自代理的结构化
状态; 冻结 LLM 的算术不可信。**

**实现决策 — 接地语音门 (grounded speech)**:
- `LanguageGenerator.describe()`: 骨架 = 感知状态直译 ("N objects in
  total: kinds. K hidden."); LLM 只润色; 输出经事实自检 (总数/隐藏数/
  种类), 任何违规回退骨架。
- 判定结果 (2026-10-29 15:09): **faith 1.0 / hall 0.0 (24/24) → M3a
  PASS**。注: 本判定口径 = 事实保真 (语言不撒谎); 流畅度/自然度是
  独立轴 (当前 LLM 润色接受率低, 回退率高, 留待 M3 之后)。
- 存档: `/root/m3a_grounding.json` (final), `/root/m3a_diag_raw_llm.json`
  (裸基线), `/root/lang_scenes.json` (v2 真值表)。

**M3b 下一步**: 指令模板 20 条 × 5 场景, 匹配 ≥0.7 且 op 不降;
语言输出 telemetry 常开。

## 8. M3b 结果 (2026-10-29)

**电池** (scripts/eval/instruction_battery.py): 5 场景 × 20 模板 = 100
trials (50 live / 50 memory)。text -> 指代 -> 脚本化 8 向贪心行走
(披露: 执行器非策略学习), 成功 = 指代正确 且 到点 (live 0.5m / memory
0.4m, ≤120 步)。基线 = 随机指代 (1/8 = 0.125)。

**v1 诊断 -> 修复 (B17)**: match 0.87, referent 0.93; 失败行显示
parsed=[] —— 根因: 词表用子串匹配, "disappea**red**" 命中颜色
"red" (单测数据恰好是红色物体而侥幸通过)。修复: 词边界匹配
(\bword\b); 反例测试 	est_disappeared_is_not_the_color_red。

**v2 判定 (2026-10-29 16:11)**:
- referent_accuracy **1.000**;  match **0.940** (live 0.880 / memory
  **1.000**);  baseline 0.125 → **M3b PASS (>=0.7)**。
- 6 个失败全部为 live 贪心行走卡墙 (无避障, 120 步上限) — 执行器
  局限, 已披露, 未调参掩盖。
- op 不变量: 电池不改训练; 训练恢复照常 (41.65M -> 41.90M)。
- 存档: /root/m3b_instruction.json (final), /root/m3b_diag_v1.json
  (bug 版诊断)。
