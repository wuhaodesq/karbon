# Stage 26 P 线 — 长程规划 (Long-Horizon Planning) 设计与基线

> Status: **design draft + baseline** (2026-11-12). 目标: 让智能体完成
> 多步目标序列 (执行功能 / 规划门), 而不是只有反应式策略。

## 1. M-P1 多步基线 (已测, 诚实数字)

设备: key_door 链式任务 (抓 obj_1 = 钥匙 -> 带到 obj_0 = 门 -> 到达),
20 回合, 66.70M ckpt:
- grasp_rate **0.80** (单步抓取在线)
- door_rate **0.05** (带物走到目标 = 断层)
- completion_rate **0.05**
→ **多步协调缺口量化: 从抓取到携带到达, 成功率 80% -> 5%**。

## 2. 规划器资产现状 (诊断)

- `LongRangePlanner` (MCTS + RSSM): 代码存在, 配置缺席 → 完全沉睡;
  且原接线只生成计划写日志 (**从不影响动作**)
- 点火评估 (自查后否决): 每周期 (2048 步) 一次计划, 深度 10,
  覆盖 ≤16 步/周期 = 0.8% 动作 — 对 ~200 步链条任务杯水车薪,
  而 MCTS 500 节点/周期纯烧算力 → **保持沉睡**
- `counterfactual_planner` 同样沉睡

## 3. 路线选择 (预注册)

**P-A (先做): 链式任务的学习强化** — 不是加更复杂的规划器, 而是
让 PPO 真正学会序列:
1. 课程: key_door 成为显式任务项 (当前 33% 随机, LP 可能不练它)
2. 塑形: 持有钥匙的接近进度 (现有: 只塑形接近钥匙与门口奖金)
3. 判据: 2-4 段后 door_rate ≥ 0.5 且 completion ≥ 0.3 (基线 0.05)
**P-A 判定 (2026-11-13): 未通过 (诚实负结果)**:
3 段强制 key_door 练习 + 携带塑形后: door 0.05→0.10, completion 0.10
(判据 door≥0.5, <0.3 = 设计级负结果); grasp 0.85→0.60 (行为重塑未收益);
67.35M 全评估物理 0.929→0.607 (副作用)。→ 回退 force_task_type;
**结论: 序列信用分配 (~200 步链的奖励归因) 是当前架构的瓶颈**,
不是"练得不够"或"塑形不够密"。P-B (技能级规划器) 成为证据支持的
下一步, 但其设计需要: 技能库检索 + 显式序列信用 (技能级回报),
不是把 MCTS 硬塞进原始动作空间。

**P-B (后做): 技能级规划器** — 用技能库 (LoRA) 做 A->B 序列选择,
真正的执行功能层; 需单独设计 (技能库检索 + 序列信用分配)

## 4. 诚实边界

- P-A 是"把多步任务学出来", 不是"规划推理"; 真正的规划器在 P-B
- 若 P-A 失败 (door_rate <0.3): 结论 = 本架构的序列信用分配是瓶颈,
  记录设计级负结果, 再评估 P-B 的必要性
