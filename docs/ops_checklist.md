# 远程运维检查清单 (Ops Pre-flight Checklist)

> 2026-11-09 立。目的: 把已发生的运维事故 (C11/C12/C13/C14/A18) 变成
> **执行前的硬性检查**, 而不是事后教训。每次对服务器做改动前逐项过。

## 每次远程操作前

1. **命令一律走本地脚本文件** → `write` 工具写脚本 → `sftp.put` →
   `sed -i 's/\r$//'` (CRLF) → `bash -n`/`py_compile` → 执行。
   **禁止**在 PowerShell here-string 里内联 `$`/`$()`/引号 (C11, 已复现
   5 次, 每次都可能静默毁掉脚本)。
2. **文档/代码只通过 write/edit 工具写入**。禁止 `Add-Content` /
   shell 重定向写中文内容 (C12: ANSI 编码污染, 已复现 2 次)。

## 清理/修剪类脚本 (C13)

3. **先在草稿目录跑** (20 个假文件 → 验证保留/删除数量)。
4. **修剪后核对数量**; 出现异常数量 (如"应有 19 只剩 7")立即停, 不回滚
   就继续跑。
5. 低数量告警必须存在 (v2 已内置: <10 个 backup 告警)。

## 评估/长任务 (A18, C14)

6. **新改动先做最小端到端冒烟** (1 任务 × 1 回合) 再跑全量; 冒烟必须
   走到改动所在的小节 (py_compile 抓不到 NameError)。
7. **与训练并发的评估一律 `MUJOCO_GL=osmesa`** (EGL 上下文冲突会崩溃)。
8. 长时间评估**先确认 JSON 路径可写** (评估在最后一节才写 JSON, 前面
   崩溃 = 全部白跑)。

## 改完后的验证 (证明活着)

9. 新进程: `pgrep -af` 确认 + 日志出现预期的第一行 (proof of life)。
10. 新配置: 从服务器侧读回关键键值 (`grep`/yaml load) 并断言。
11. 训练/链: 改完 5 分钟内 `tail watch_night.log` 确认段在跑。
